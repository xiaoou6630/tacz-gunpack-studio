# 为什么不能一键生成一把枪

## 一句话答案

因为**好不好看这件事，没法写成参数**。

工具能帮你干的是对路径、写 JSON、跑校验、卡流程；它帮不了你的是决定这把枪该长什么样。

---

## 那个"确定性"到底确定在哪

你可能会看到宣传说这套流程"确定性"、"可复现"。这个词容易误解，先说清楚：

**确定的是流程，不是形状。**

| 环节 | 会不会出岔子 | 靠什么保证 |
|---|---|---|
| 到第几步了 | 不会 | 阶段只能按顺序走，跳不过去 |
| 该谁干活 | 不会 | 每个阶段绑定固定角色，别人推进直接报错 |
| 东西做没做出来 | 不会 | 工具去磁盘上查文件，不听 AI 说自己做完了 |
| 审核还算不算数 | 不会 | 审核结果绑定文件指纹，文件一改审核自动失效 |
| 中断了能不能接着做 | 不会 | 进度存在 `.tacz/builds/<枪名>.json`，随时可以续 |
| 能不能算完工 | 不会 | 必须你本人在游戏里试过并确认，才允许标记完成 |
| **枪好不好看** | **会** | **这是审美，只能你来判断** |

---

## 为什么不做一键生成

### 第一，枪的形状是审美

一把枪"像不像"，取决于这些：

- 机匣和枪管的**比例关系**
- 导轨的**齿型和节奏**
- 贴图的**明暗交界**、饱和度
- 第一人称下的**手位和视差**

这些都没法从数字算出来。真做成一键生成，形状可能"对"，但一眼就是方块拼的。

### 第二，TACZ 的坑全在细节里

实际踩过的：

| 你在游戏里看到的 | 真正的原因 |
|---|---|
| 改枪界面里枪飞到天上 | 模型缺 `refit_*_view` 组 |
| 配件装不上 | `allow_attachment_types`、`allow_attachments` 标签、`*_pos` 定位组，三样缺一样 |
| 动画不播 | display 里写了 `.animation` 后缀，或片段名和状态机对不上 |
| 弹药模型 404 | 弹药路径是 `geo_models/ammo/<id>.json`，**不带** `_geo`；枪却是 `gun/<id>_geo.json` |
| 槽位图糊 | 拿 HUD 尺寸当槽位图用，或者没关阴影 |

这些靠"生成器猜"是猜不中的，只能一条条对着官方基准核。

### 第三，美术和数据必须能分开改

数据那边改完 display 字段，美术这边重导出几何**不能**把 JSON 冲掉。

如果做成一个"一键生成"，两边就会互相覆盖，而且出事后没人知道是哪一步覆盖的。

## 那到底自动化了什么

| 自动干了 | 对应工具 |
|---|---|
| 建包骨架、校验、打包 | `tacz_pack` |
| 建枪工程、导出几何和 UV | `tacz_gun` |
| 弹药、配件的模型和图标 | `tacz_ammo` / `tacz_attachment` |
| 按官方口径出两种图标 | `tacz_icon_render` |
| 写 index / data / display / 语言 / 配方 / 标签 | `tacz_item` |
| 把 display 里每个引用对着磁盘查一遍 | `tacz_verify` |
| 卡阶段、卡产物、卡人工验收 | `tacz_build` |
| 从官方仓库取基准文件 | `tacz_spec` |
| 从审核缺陷里提炼经验、改写技能 | `tacz_skill` |

**你负责的**：决定做哪把枪、形状像不像、手感对不对、进游戏验收。

## 关于 blueprint：它不是模型

有个容易误会的地方。

流程里有个 `BLUEPRINT` 阶段，要求产出一个 `models/<枪名>-blueprint.json`。这个名字听起来像"模型定义"，但**它不是**。

- **没有**任何代码会把它变成几何
- 它的 `parts[].cubes` 字段**永远是空的**
- 它的真实用途是两张清单：

| 给谁 | 干什么用 |
|---|---|
| 建模的人 | 知道有哪些部件、每个部件挂哪根骨骼、大概多大 |
| 审核的人 | 知道这把枪该有的部件齐不齐 |

几何是在 Blockbench 里建的，只能在那里建。blueprint 只是"施工单"。

## 和"让 AI 自己随便做"比，卡流程解决了什么

| 放任 AI 自己做 | 卡流程之后 |
|---|---|
| AI 说"做完了"，其实没做 | 工具去磁盘上查，不听它说 |
| 你中途关掉，进度全丢 | 进度存盘，随时接着做 |
| 审核口头说"过了" | 审核绑定文件指纹，改一个字节就失效 |
| 模型改完，旧审核还算数 | 同上，指纹不匹配就拦住 |
| AI 自己就打 zip 交付 | 打包阶段没通过，不许进下一步 |
| 没人真进游戏试过就宣布完成 | 必须你本人确认才算完 |

这套做法借鉴的是工程上通用的"产物驱动 + 门禁 + 可恢复"，不是某个具体项目的代码。
